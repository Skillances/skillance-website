# Hosting on Azure Static Web Apps

The site is an Azure Static Web App in `rg-skillance-prod`:

| Resource | Value |
|---|---|
| Static Web App | `swa-skillance-web-53be9f` (Standard) |
| Region | East US 2 (Static Web Apps has no South Africa region; West Europe was not accepting new customers) |
| Default address | `mango-bay-069ad4c0f.4.azurestaticapps.net` (Azure-generated, never shown to visitors) |
| Domains | `skillance.co.za` (A record to `20.22.31.128`) and `www.skillance.co.za` (CNAME to the default address) |

Static files are served through Azure's edge network, so deploys swap atomically with no downtime.

## What lives where

- `public/staticwebapp.config.json`: security headers (CSP, HSTS, ...), SPA fallback, redirects, caching and
  MIME types. Copied into `dist/` at build time.
- `swa-api/client-log/`: the Azure Function behind `POST /api/client-log`. Its `index.js` is generated by
  `scripts/build-swa-api.mjs`, which bundles `api/client-log.js` (the shared, hardened handler).
- App setting `CLIENT_LOG_PROXY_HOPS=2`: Static Web Apps appends two proxy hops to `X-Forwarded-For`, so the real
  client is the second-to-last entry. Entries earlier in the list are client-controlled and are ignored.

## Deploying

`.github/workflows/deploy-static-web-app.yml` runs on every push to `main`: typecheck, tests, lint (reported,
not blocking), build the function and the site, deploy with `Azure/static-web-apps-deploy`, smoke-test the site,
then ping IndexNow.

It needs one repository secret, `AZURE_STATIC_WEB_APPS_API_TOKEN`:

```bash
az staticwebapp secrets list -n swa-skillance-web-53be9f -g rg-skillance-prod --query properties.apiKey -o tsv
```

Optional repository variables, compiled into the bundle at build time: `VITE_API_BASE_URL`
(defaults to `https://api.skillance.co.za`), `VITE_AUTH_REFRESH_COOKIE`, `VITE_PUBLIC_S3_CATEGORY_BASE`.

Manual deploy:

```bash
node scripts/build-swa-api.mjs
VITE_API_BASE_URL=https://api.skillance.co.za npx tsc -b && npx vite build
SWA_CLI_DEPLOYMENT_TOKEN=<token> npx @azure/static-web-apps-cli deploy ./dist --api-location ./swa-api --api-language node --api-version 20 --env production
```

## Limits and trade-offs

- Not hosted in South Africa. If that becomes a hard requirement again, the alternative is App Service in South
  Africa North (needs a Standard plan or higher for deployment slots to avoid restart downtime).
- Static Web Apps cannot choose a response from the `Accept` header, so the old "serve markdown to agents on `/`
  and `/beyond`" negotiation is gone. The static mirrors (`/beyond.md`, `/llms.txt`, `/faq.md`, ...) still work.
- The client-log rate limit is in memory per function instance.
- `vercel.json` is kept only as the CSP reference for `tests/hosting-headers.test.ts`; delete both together once
  Vercel is gone.
